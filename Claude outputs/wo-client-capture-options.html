Client capture on the work order — no more "Mike"

Today the client box is one search field whose last row is "+ New client: 'mike'" — one tap and "mike" is a client profile with no last name, no phone, nothing. And a work order saves fine with no client at all. Four changes below, all on the same block, plus the CRM line. Everything shown is doable; the pieces (search, profile create, the CRM's confirm-client modal) already exist and just need to be wired to the calendar path.

1Search results you can actually recognise

Typing "mike" today lists names and nothing else. Now each row says what kind of client, a phone tail, how many sessions, and when the last one was — enough to know it's that Mike. The create row is separated, green, and says what it does.

4The CRM line, written for you

Every confirmed session saved from the calendar that didn't come from a lead writes one Booked line in the CRM — linked to the client and the work order, tagged from calendar. Re-saving doesn't duplicate it. Booked counts and conversion see it; you can also see how many bookings skipped the CRM.

5Rules, in one place

QuestionAnswer
Can a WO save with no client?Tentative: yes, with a name (warm "Not on file" chip). Confirmed: no — the stop in part 3.
What makes a valid new client?First + last name, and a phone or an email. Label/Billing: company name + an A&R first/last + phone or email.
Duplicate checkSame phone or email anywhere on file → hard "Looks like". Same first name + last name within one letter → soft "Looks like". Must be answered.
Old sessions with "mike"Untouched. They wear the warm chip; a "Put on file" button fixes each in 20 seconds. A one-time list of them can go on your dashboard if you want to clear them.
Runners?Runners never touch the client block — this is office and owners only.
DataOne column: work_orders.lead_id (so re-saves don't write a second lead). Leads get source = 'Calendar' and created_by_name. Everything else exists.
