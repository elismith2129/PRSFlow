Mic inventory — a mic that moved is not a mic that's missing

ERS report, Sep 15: "if something is transferred, it shouldn't look like it was missed or is missing." Today the ERS closer can already tap a PRS mic HERE on the PRS tab. The problem is at PRS: the reference line just says last: HERE · 9/14 without saying where, so the PRS closer marks it missing and the streak alert runs every night it's on loan.

Nothing new to store. Every checkin already records which studio made it. Option A changes what the home page says about it, not what's saved.

What changes in code. The reference query on the mics page selects studio alongside status/room/date. refLine says "at ERS since …" when the prior studio ≠ this page's studio and the status was here/room. Away mics leave doneCount's denominator and missingMics. The popover's first option reads "Back at PRS" for an away mic (it is HERE — same write). The home tab appends the "Also here" list: mics with home ≠ this studio whose latest prior checkin was made by this studio. Admin Mic Inventory's status column gets the same "at ERS" wording. Missing streak in admin ignores checkins from a studio other than the one that saw it last.

BAn explicit TRANSFERRED status

A fourth checkin status with a destination: the popover gains "Transferred → ARS / ERS / PRS / TRK". Either end can mark it.

Same sentence, more ceremony. "Transferred to ERS" and "last seen HERE by the ERS closer" carry identical information. B adds a check-constraint change, a destination picker, admin history that mixes two ways of saying one thing, and a question A never has to ask: who marks it — the sender, the receiver, or both, and what if they disagree? It also fails the moment nobody marks it, which is exactly the night it matters. A works off the tap the receiving closer already makes.

CMove it — change the mic's home (exists today)

Admin → Mic Inventory → Manage Mics → home studio. The right tool for a mic that has permanently moved. Not for a loan.
