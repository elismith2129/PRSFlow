Adding a PO after approval

Everything up to “sent” is built and staying. This is only about what happens after an owner has approved — and the answer splits cleanly in two.

1 · Something was wrong. Any correction to the work order goes back through the whole loop — review, new invoice, owner re-approves. No exceptions, no shortcut. That already happens by itself: change the money and the row drops out of Approved and back into the owner’s queue.

2 · Nothing was wrong, the PO just came late. Never goes back to the owner. But it is not one field — the label issues the PO, the invoice is re-cut carrying it (often a new invoice date), the new PDF is attached, and the package goes out. Four acts, one intention, and today they are four different screens.
A · The row’s next action becomes “Add PO”, and it opens the whole flowRecommended
An approved package that can’t go out because it has no PO currently shows a greyed Download and a chip explaining why. Instead the button becomes the thing you actually came to do. One panel: type the PO, drop the re-issued invoice, send — the package rebuilds itself in between. No owner, no re-approval, no trip to the work order.

Then the row’s button is Mark sent, exactly as it would have been if the PO had been there all along. The approval is untouched throughout — the money never moved, and the money is the only thing an owner signed.
If it was already sent and the PO turns up afterwards (a no-PO-needed job that later needed one), the same panel opens from ⋯ → Add PO & re-send: same three steps, and it re-stamps the sent date because a second document really did go out. The aging clock keeps its ORIGINAL date — the client has owed this since the first send.
B · A · plus “Awaiting PO” as its own tab
Everything in A, and the waiting rows get a home. A PO can take weeks, so those rows sit in In progress looking like unfinished work — and the pile is invisible unless you scroll. A tab makes “what are we waiting on labels for?” one click, and its count is the number to chase. Same argument as Balance due leading the COD side.

C · Inline on the row (recorded as the weak option)
Type the PO straight into a cell, drop the PDF on the row, button flips to Download. Fewest clicks in the best case — but it hides that a PO means a NEW INVOICE, so the likely outcome is a PO typed with the old PDF still attached and a package that goes out contradicting itself. The flow in A exists precisely to make the second step unmissable.
