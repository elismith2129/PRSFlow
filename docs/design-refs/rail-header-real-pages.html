What a dev would tidy

Proposed, in the order I'd build them after the rail + CRM split. None of it changes what staff do, only how many versions of the same thing exist.

1One page header, used by every page.

Today there are five versions: big title-words (CRM, Billing, Daily Ops), a 22px title (Lakers, SRS, Petty Cash), a small label over a title (Engineers, Shift Notes), a lone 26px title (Training), and no title at all (Memos, Punches, Hiring, Positions).

2One search, in one place.

At least six places have their own search box, each built differently (All Leads, Clients, Registrations, Texting, Billing Hub, Engineers). The top bar becomes the only one and each page tells it what to search. The dashboard has no search.

3One rule for tabs.

Underlined words switch the view. Pills filter the list you're on. Today pills and big words are both used for both jobs.

4The view goes in the address.

Opening Clients becomes /crm?view=clients, so the back button, bookmarks and links from the dashboard land on the right tab. Texting gets its own address; old links keep working.

5Who-sees-what in one list.

Each rail item carries its own roles instead of a chain of if-statements. Same rules as today (flip "View as" above to check them), harder to break when a page is added.

6One page width and spacing.

Pages set their own max width (780, 860, 980, full) and the CRM runs at 90% zoom to fit. One content width and one gap scale, then the zoom can go. Last, and page by page.
