One press for a blanket booking

Two days, five rooms, one price. Today that is twelve actions on the work order. This page is the two changes that make it one press — and make every later edit start from the right number. Nothing about how a blanket day is stored or edited afterward changes; the day header still owns the price.

The default was the bug. Adding ERS B beside ERS A copied A's $3,150 onto B. The blanket allocates by that number, so one inherited rate quietly skews every room's share. A rate should come from the room, not from the row above it. That is what a rate table is for.

1Room rates become a table Build first

room_rates: one row per room, day rate, hourly = day ÷ 10 (house law). Read wherever a room is picked and no rate exists yet — the Add-dates prompt, the Seed panel, a blank row's room dropdown. It only fills; it never overwrites a rate someone typed. Edited in Admin → Rates. Seeded from the rate sheet with Paramount A corrected to $1,750.

2The Seed panel takes rooms, plural, and a blanket price Then this

A seed group already has one room, a date range, times, a rate, staff. The room becomes a set of chips; each picked room shows its rate from the table (editable); an optional Blanket rate / day and OT turn every day of the range into a bundle. One press.
