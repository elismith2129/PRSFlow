Flags — one page, two departments

A flag is anything that needs doing. A task is a flag someone typed by hand. A flag is never nobody's: its kind decides its department the moment it exists, so there is no grabbing and no unassigned pile. Two departments: Tech (Facility, Gear) and Admin (Clients & billing, Office). Tech sees only Tech's list; Admin sees everything, plus what they've handed out. Nothing on the page is red except age.

Rulings to confirm before CC touches anything

  1. Four kinds, two departments. Facility and Gear (mics are gear) → Tech. Clients & billing and Office → Admin. Kind is set at creation and decides the department. Runner checklist flags default to Facility; work-order flags default to Office. Admin can change a kind, which moves the flag.
  2. No grab, no unassigned, no acknowledge. Being on the department list is the acknowledgment. Admin may put a person's name on a flag; that's the only assignment step that exists.
  3. Visibility is by department. Tech (Sierra, Tom) sees all Tech flags, any name, and nothing else. Admin (owner, manager, billing, asst_manager) sees everything. Tech gets the Runner tab of Shift Notes, not the Manager tab.
  4. I assigned is each Admin person's tracking list — every flag they typed or named someone on. Hot at 72h on both lists.
  5. Done asks for vendor + cost only on Tech flags. Everything else is done with an optional note. "Not a real issue" closes with a note, no cost.
  6. Mic QC becomes a source: a bad or missing mic on the runner mics page makes a Gear flag for Tech. The Admin banner goes away.
  7. Data: dashboard_tasks is the flag row (+ studio, kind, department, done_vendor, done_cost). flags stays as intake for the runner checklist / WO popup and mirrors state, so Admin's Flags tab keeps working. Tech RLS widens from own-only to department = tech; Admin roles read all.
  8. Rail: one item, Flags, under Operations. Tasks item retired; /tasks becomes a redirect stub. Dashboard "Your List" rows link here.
