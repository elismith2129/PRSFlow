The COLLECT display

A runner reads Balance Due $180.00, quotes it, runs $180 on the terminal, then picks Credit Card — and the studio eats $5.24. The bug is that the cash number and the card number appear at different times. Fix: never show one without the other. Both amounts, equal weight, before anything is selected; then the method pick fills the matching amount.

Nothing about the money model changes. The 3% stays attached to each payment (payment_rows.fee_amount, cardFeeOfCharged), never to the invoice — deposits, OT after the fact and split payments all keep working exactly as today. This is a display and a pre-fill. No migration.

2Rules this locks in

Equal weight, same colour, same size — never bold one and footnote the other. Both before selection — the block renders on open, not on method pick. Pick fills, never overrides a typed amount — choosing a method on a row that already has an amount leaves the amount alone (a runner who typed $100 meant $100). The dropdown shows the number next to the method — the decision and the amount are in the same place. History is separate — fees already collected never fold into the collect number. Runner and admin see the same block — one component, one behaviour. Cash line uses the balance; card line uses cardTotalForBase(balance) — the existing helper, no new math.
